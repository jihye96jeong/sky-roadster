# 게임 프리뷰 영상 + X 포스트 제작 프롬프트

다른 웹 게임 프로젝트 세션에 아래 블록을 그대로 붙여 넣고 `{ }` 부분만 채워서 사용.

```
현재 프로젝트 게임의 "실제 플레이" 프리뷰 영상과 X(트위터) 포스트 문구를 만들어줘.
계획만 말하지 말고 영상 파일까지 실제로 만들어서 전달해줘.

[게임 정보]
- 게임 이름: {게임 이름}
- 배포 URL: {https://...}
- 핵심 조작/목표 한 줄: {예: 버튼 하나로 상승·하강하며 게이트 통과}
- 보여주고 싶은 장면(선택): {예: 시작 화면 → 첫 입력 → 플레이 → 클리어 연출 → 결과}

[1. 프리뷰 영상 — 실제 플레이만]
- AI 생성 영상·자막·인트로 없이, 게임 화면 그대로의 실제 플레이를 담는다.
- 한 판을 끊김 없이 이어서 녹화(장면 건너뛰기·짜깁기 금지). 시작 화면 → 첫 입력 → 플레이 → 클리어/결과까지.
- 빨리 감기 1.5~1.6배속으로 최종 길이 약 15~25초. 1280×720, 30fps, H.264 MP4(yuv420p, faststart).
- 소리는 없어도 된다(브라우저 WebAudio는 이 방식으로 녹음되지 않음 — 결과 보고에 명시).

[녹화 방식 — 실시간 화면 녹화 대신 결정적 프레임 캡처]
1. 먼저 코드를 확인하고, 없으면 디버그 훅을 추가한다:
   - 게임 루프 일시 정지(freeze), 지정 시간만큼 게임 진행(step(dt) → update + render),
   - 입력 주입(hold/press 등), 게임 상태 조회. 일반 플레이에는 영향 없게.
2. Playwright + 설치된 Chrome(channel="chrome")을 GPU로 실행:
   args = ["--use-angle=d3d11","--enable-gpu","--ignore-gpu-blocklist","--enable-gpu-rasterization"]
   (SwiftShader 소프트웨어 렌더링은 프레임당 수 초로 너무 느림. WebGL 렌더러 이름을 출력해 GPU 사용 확인)
3. 매 프레임: 게임을 (배속/30)초 진행 → 스크린샷(JPEG q90) 저장.
   - CSS 애니메이션·트랜지션(팝업, 배너 등)도 같은 가상 시간으로 맞춘다:
     document.getAnimations()를 pause하고 currentTime을 프레임마다 (1000×배속/30)ms씩 직접 진행.
   - 튜토리얼·첫 방문 안내 등 영상에 불필요한 오버레이는 localStorage 등으로 미리 끈다.
4. 플레이는 사람처럼 보이는 봇으로: 0.08~0.16초 간격 랜덤 판단 + 목표에 약간의 오차.
   너무 완벽하게만 플레이하지 않게(가끔 PERFECT를 놓치는 정도).
5. 첫 60프레임 정도로 속도를 측정해 예상 소요 시간을 먼저 보고하고, 오래 걸리면 백그라운드로 실행.
6. ffmpeg로 인코딩: ffmpeg -framerate 30 -i frames/%05d.jpg -c:v libx264 -crf 18 -pix_fmt yuv420p -movflags +faststart promo/{이름}-gameplay.mp4
7. 결과 영상에서 프레임 8장 정도를 타일로 뽑아(ffmpeg tile) 직접 확인한 뒤 전달.

[주의 — 이전 작업에서 겪은 문제]
- Windows 경로 길이 제한(260자): 임시 폴더 경로가 길면 스크린샷 저장이 실패한다. 짧은 파일명/폴더 사용.
- 로컬 서버가 꺼져 있으면 ERR_CONNECTION_REFUSED. 녹화 전에 서버 상태 확인.
- 영상 파일은 promo/ 에 저장하고 .gitignore 에 promo/*.mp4 추가(대용량 바이너리 커밋 금지).
- 녹화 스크립트는 tools/record_gameplay.py 로 저장해 재사용 가능하게(사용법을 docstring에).
- .env·API 키는 영상·로그·커밋 어디에도 노출 금지.

[2. X 포스트 문구]
- 제작 기간은 git log 첫·마지막 커밋 시각으로 근거 있게 산정(실작업 시간을 부풀리지 말 것).
- 사용한 모델·도구를 사실대로: {예: Claude Opus 5.5 (Claude Code), 에셋은 xAI Grok Imagine}.
- 메인 포스트: 280자 이내, 첫 줄 훅 + 한 줄 게임 소개 + "무슨 모델로 얼마 만에" + 배포 링크.
- 답글용 짧은 포스트 2~3안: (a) 도전형 CTA("점수 답글로 남겨줘") (b) 제작 과정 한 줄 (c) 담백한 감사형.
  어떤 안을 추천하는지와 이유를 짧게.
- 영어 기본, 한국어 버전도 함께.
- 실제 브랜드·상표(예: 자동차 회사)를 언급·태그하면 공식 협업처럼 보일 수 있으니
  "fan-made / not affiliated" 표기 여부를 함께 제안.
- 영상이 빨리 감기라면 그 사실(예: 1.6× speed)을 표기할지 제안.

[최종 보고]

- 녹화 환경(GPU 렌더러 이름, 프레임당 소요 시간), 확인한 장면.
- 포스트 문구(메인 + 답글 안), 추천안과 이유.
```
